###Intelligent Process Controls and Exceptions Handling 

In the UK, home services companies like British Gas, HomeServe, and Hometree are well known for providing comprehensive home emergency and appliance cover that typically includes boilers, plumbing, drainage, electrics, and kitchen appliances.

We have created an AI solution for the customer fulfilment (which refers to end-to-end operational execution required to deliver on the promises made to a customer—whether that is delivering a home care service, or completing an engineering visit) team in home-services companies. 

The tool will act an integrated operational monitoring and exception processing suite.

The proposed solution involves deploying multiple AI agents to orchestrate the workflow-
Agent 1 (Knowledge base & controls generation): Reads the terms and conditions, policy documents, SOPs, cover plan etc. Extracts rules and generates controls across the operations.

Agent 2 (Schema mapping, Query Generation & Fallout Extractor): Reads the datasets and metadata for the datasets. For each control defined by Agent1, this agent writes SQL queries, creates controls datasets. Using the validation rules for controls, Agent2 detects process fallouts.

Agent 3 (Exception Handler): Across all the controls, it decides the course of action & classifies the fallouts into 2 pots- AI fixable and Review required. Once approved after human review, the AI agent executes approved actions across systems or hands off complex cases.

Agent 4 (Dashboard): Gives a summary of all the actions- Controls Executed, Controls with Fallouts, Fallouts breakdown (AI Fixable, Review required), Outcome (fixed, skipped, rejected)

In a multi-agent orchestration pattern, a complex goal is broken down into smaller sub-tasks assigned to specialized AI agents—each with its own prompt, system role, tools, and context window—working together toward a unified output.

Instead of relying on a single large context window or monolithic model to do everything, orchestration distributes responsibility, improving reliability and reasoning precision.

Our solution uses Sequential Pipeline Architecture. 
How it works: Output from Agent $A$ becomes the input for Agent $B$, which feeds into Agent $C$.

Having LLM agents write and execute raw code directly on live production databases carries significant risks. Instead, the most feasible implementation leverages agents to operate as a reasoning and orchestration layer on top of structured schemas, pre-defined query templates, and action APIs.

## Proposed Changes

### [NEW] `app.py` (file:///c:/Users/91993/Desktop/Smart%20controls/app.py)
A new FastAPI server that will handle the following endpoints:
- `POST /api/upload`: Upload files directly to `inputs/context_docs/`
- `POST /api/agent1/run`: Execute Agent 1 to parse documents, generate controls, and return results.
- `POST /api/agent2/run`: Execute Agent 2 to analyze datasets, write SQL queries, and extract fallouts.
- `GET /api/agent3/exceptions`: Fetch the list of exception records requiring human review.
- `POST /api/agent3/decide`: Submit human review (Approve / Reject / Skip) for a fallout. This will run Agent 3's LLM draft logic asynchronously for approved cases.
- `POST /api/agent4/run`: Collate outcomes and generate dashboard analytics.
- `GET /api/download/{report_type}`: Downloader endpoints for generated JSON and reports.
