# INPUT METADATA SCHEMA (DATA DICTIONARY)

### Table 1: Customer (`Customer`)
- `AccountNumber` (STRING) - 12-digit unique account identifier starting with '91' [PK]
- `IsVulnerable` (BOOLEAN) - Flag indicating if an occupant has vulnerable/medical risk status
- `SupplyAddress` (STRING) - Physical address of the covered property

### Table 2: Contract (`Contract`)
- `ContractId` (STRING) - 10-digit annual policy identifier starting with '16' [PK]
- `AccountNumber` (STRING) - Link to Customer [FK]
- `ContractStartDate` (DATE) - Policy coverage start date
- `ContractEndDate` (DATE) - Policy coverage expiry date
- `ContractStatus` (STRING) - Active, Completed, Lapsed, Cancelled
- `ContractCost` (DECIMAL) - Total annual/policy cost

### Table 3: Product (`Product`)
- `ProductId` (STRING) - Unique product coverage line item ID [PK]
- `ContractID` (STRING) - Link to Contract [FK]
- `ApplianceType` (STRING) - Boiler, Central_Heating, Radiator, Gas_Appliance, Kitchen_Appliance
- `ProductStartDate` (DATE) - Coverage start date for product
- `ProductEndDate` (DATE) - Coverage end date for product
- `ProductCost` (DECIMAL) - Standalone product price
- `AsvIncluded` (BOOLEAN) - Flag indicating inclusion of Annual Service Visit for gas appliances
- `Excess` (INTEGER) - Applicable excess amount per claim (0, 30, 60)

### Table 4: DirectDebit (`DirectDebit`)
- `DDId` (STRING) - Unique Direct Debit mandate identifier [PK]
- `ContractID` (STRING) - Link to Contract [FK]
- `DDDate` (DATE) - Date Direct Debit schedule was executed/set up
- `DDAmount` (DECIMAL) - Recurring payment collection amount
- `DDFrequency` (STRING) - Monthly, Annual
- `DDStatus` (STRING) - Active, Inactive

### Table 5: ContractualBilling (`ContractualBilling`)
- `SDDocumentId` (STRING) - Unique contractual billing invoice/document ID [PK]
- `ContractID` (STRING) - Link to Contract [FK]
- `SDDate` (DATE) - Invoice issuance date
- `SDDueDate` (DATE) - Payment due date
- `SDAmount` (DECIMAL) - Contractual billing charge amount
- `SDClearingDocumentId` (STRING) - Reference to PaymentTransaction.PaymentDocumentId [FK]
- `SDClearingAmount` (DECIMAL) - Cleared payment amount
- `SDClearingDate` (DATE) - Date payment was settled
- `SDClearingStatus` (STRING) - Pending, Cleared, Failed, Partially_Cleared


### Table 6: JobBooking (`JobBooking`)
- `WorkOrderNumber` (STRING) - Unique work order identifier [PK]
- `ContractID` (STRING) - Link to Contract [FK]
- `WorkOrderCategory` (STRING) - Emergency, Priority, Standard
- `WorkOrderType` (STRING) - Breakdown, Repair, Annual_Service, Inspection
- `ApplianceType` (STRING) - Boiler, Central_Heating, Radiator, Gas_Appliance, Kitchen_Appliance
- `ProductId` (STRING) - Unique appliance/asset identifier [FK]
- `WorkOrderCreatedDate` (DATETIME) - Date and time job order was opened
- `HasHeatingHotWater` (BOOLEAN) - Flag indicating loss of heating or hot water
- `IsUncontainable` (BOOLEAN) - Flag indicating leak is uncontainable
- `PropertyDamageRisk` (BOOLEAN) - Flag indicating active property damage risk
- `WorkOrderStatus` (STRING) - Open, Closed

### Table 7: EngineerVisit (`EngineerVisit`)
- `BookingID` (STRING) - Unique engineer appointment visit ID [PK]
- `WorkOrderNumber` (STRING) - Link to JobBooking [FK]
- `EngineerId` (STRING) - Unique engineer identifier
- `ProposedStartDate` (DATE) - Scheduled arrival start date
- `ProposedStartTime` (TIME) - Scheduled arrival start time
- `ProposedEndDate` (DATE) - Scheduled arrival end date
- `ProposedEndTime` (TIME) - Scheduled arrival end time
- `ActualStartDate` (DATE) - Actual engineer arrival date
- `ActualStartTime` (TIME) - Actual engineer arrival time
- `ActualEndDate` (DATE) - Actual engineer departure date
- `ActualEndTime` (TIME) - Actual engineer departure time
- `VisitStatus` (STRING) - Scheduled, Dispatched, Completed, Missed, Aborted
- `EngineerNotes` (STRING) - Field notes and repair outcome details

### Table 8: NonContractualCharge (`NonContractualCharge`)
- `NBDocumentId` (STRING) - Unique non-contractual charge document ID [PK]
- `WorkOrderNumber` (STRING) - Link to JobBooking [FK]
- `NBDate` (DATE) - Date non-contractual fee was raised
- `NBType` (STRING) - Excess, OutOfScopeParts, Parking, CancellationFee
- `NBDueDate` (DATE) - Due date for non-contractual fee
- `NBAmount` (DECIMAL) - Monetary value of charge
- `NBClearingDocumentId` (STRING) - Reference to PaymentTransaction.PaymentDocumentId [FK]
- `NBClearingAmount` (DECIMAL) - Amount paid against charge
- `NBClearingDate` (DATE) - Date non-contractual charge was cleared
- `NBClearingStatus` (STRING) - Pending, Cleared, Failed
- `IsPreauthorized` (BOOLEAN) - Flag if customer pre-approved charge before work execution

### Table 9: PaymentTransaction (`PaymentTransaction`)
- `PaymentDocumentId` (STRING) - Unique payment record ID [PK]
- `ContractId` (STRING) - Link to Contract [FK]
- `TransactionType` (STRING) - ContractualBilling, Excess, Refund, Compensation, NonContractual
- `PaymentAmount` (DECIMAL) - Transaction monetary amount
- `PaymentDate` (DATETIME) - Date and time payment was processed
- `PaymentStatus` (STRING) - Success, Failed, Pending, Refunded
- `PaymentClearingDocumentId` (STRING) - Reference to SDClearingDocumentId or NBClearingDocumentId [FK]

### Table 10: Correspondence (`Correspondence`)
- `CorrespondenceId` (STRING) - Unique correspondence log ID [PK]
- `ContractId` (STRING) - Link to Contract [FK]
- `Channel` (STRING) - Email, Letter, SMS
- `SentTimestamp` (DATETIME) - Date/time notice was dispatched
- `CorrespondenceType` (STRING) - DD_Advance_Notice, Policy_Schedule, Renewal_Notice, Cancellation_Letter

### Table 11: CustomerContact (`CustomerContact`)
- `ContactId` (STRING) - Unique interaction log ID [PK]
- `ContractId` (STRING) - Link to Contract [FK]
- `ContactChannel` (STRING) - Inbound_Call, Outbound_Call, WebChat, App
- `ContactTimestamp` (DATETIME) - Date/time interaction occurred
- `Reason1` (STRING) - High-level operational category (e.g., Billing, Booking, Claims)
- `Reason2` (STRING) - Specific operational sub-category (e.g., Chase Visit, DD Query)

### Table 12: CustomerComplaint (`CustomerComplaint`)
- `ComplaintId` (STRING) - Unique complaint ticket ID [PK]
- `ContractId` (STRING) - Link to Contract [FK]
- `LoggedTimestamp` (DATETIME) - Date/time complaint was registered
- `ResolvedTimestamp` (DATETIME) - Date/time complaint was officially closed
- `Status` (STRING) - Open, Under_Investigation, Resolved, Escalated_FOS
- `Reason1` (STRING) - High-level complaint root cause (e.g., Engineer Performance, Incorrect Billing)
- `Reason2` (STRING) - Specific complaint sub-cause (e.g., Late Arrival, Uncollected Excess)
